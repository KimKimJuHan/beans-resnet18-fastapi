## 3. 오류 이력 (실제 겪은 것)

| 오류 ID | 현상 | 원인 확인 | 조치 | 재검증 | 결과 |
|---|---|---|---|---|---|
| E-01 | `python3.11: command not found` | WSL에 Python 3.14만 설치됨 | conda로 3.11 환경을 만들고 `~/venvs/beans311` venv 생성 | `python --version` | 3.11.17 |
| E-02 | `requirements.txt` 없음 | 교재의 폴더 생성 명령만 실행하고 파일은 배치하지 않음 | 교재 01·02 코드를 프로젝트로 구성해 배치 | `ls requirements.txt` | 정상 |
| E-03 | 제공 데이터 폴더가 `train/train/<클래스>`로 겹침 | 압축본을 풀 때 상위 폴더가 한 번 더 생김 | 한 단계 올려 `train/<클래스>` 구조로 정리 | `check_dataset.py` 개수 | 1034/133/128 |
| E-04 | Celery `Cannot connect to redis://127.0.0.1:6379/2: Connection refused` (51회 재시도) | Docker Desktop이 실행되지 않음 (`docker: command not found in this WSL 2 distro`) | Docker Desktop 실행 → `docker compose up -d redis postgres` | Celery 로그 | 11:11:04 Connected → ready (Worker 재시작 없이 자동 재연결) |
| E-05 | `uvicorn: command not found`, `reports/evidence` 없음 | 터미널이 conda `(base)` 환경, 다른 프로젝트 폴더(`~/fastapi_sentiment`)에 있었음 | `conda deactivate` → `source ~/venvs/beans311/bin/activate && cd ~/fastapi_resnet18` | `uvicorn.log` | Application startup complete |
| E-06 | `FLUSHDB` 후에도 화면에 `cache_hit:true` | 버튼을 여러 번 눌러서 첫 MISS 결과가 이후 HIT 결과로 덮임 (서버 로그상 연속 POST 19회) | 캐시를 비운 뒤 **한 번만** 클릭 | `sync_angular.png` | `cache_hit:false`, 21.77ms |
